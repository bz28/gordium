# regulations

All rule **data**: the city's documents and the rulebooks built from them. No code lives here.

- `document_extraction_guide/` — how we turn any regulation document into rules (shared by every place).
- `jurisdictions/<state>/<place>/` — one folder per city or town, worked through in numbered steps:

| Step | Folder | What it is | Who changes it |
|---|---|---|---|
| 1 | `1_source_documents/` | Original documents, plus `sources.yaml` (link, download date, fingerprint) | Never edited |
| 2 | `2_extracted_text/` | Text pulled out of the documents | Generated by code only |
| 3 | `3_section_labels/` | Each clause labeled Rule / Flag / Reference / Not for checking, plus a topic | Drafted, architects confirm |
| 4 | `4_term_definitions/` | How this place defines height, story, grade plane… | Architects confirm |
| 5 | `5_zoning_rules/` | **The rulebook**, one file per district (`R-1b.yaml`) | Architects approve |
| 6 | `6_coverage_report/` | Proof that no part of the documents was skipped | Generated by code only |
| 7 | `7_published_rulebooks/` | Frozen versions the checker uses | Never changed once made |

## When the city changes its code

Download the new documents (step 1) and re-run the steps. Code compares the new draft with the approved rules and sends **only the differences** to the architects. Approved rules are never overwritten automatically.

## Two different approvals

- **Rule approval** — once per code version: an architect confirms each rule is right (step 5).
- **Project confirmation** — once per project, in Rhino: the architect confirms the facts about their site and design (lot, zone, use…).
