# regulations

All rule **data**: the city's documents and the rulebooks built from them. No code lives here.

- `document_extraction_guide/` — how we turn any regulation document into rules (shared by every place).
- `jurisdictions/<state>/<place>/` — one folder per city or town, worked through in numbered steps (below).
- `jurisdictions/<state>/<state>_state/` — the state's own law that every place in the state inherits (New York's Residential Code: `new_york/new_york_state/`; a state may have more than one, each a book for different buildings: New York's Building Code, `new_york/new_york_state_building/`), in the same numbered steps. Its settings file is `state.yaml`, so it is no place; a place lists it under `inherits:` in its `jurisdiction.yaml`. A copyrighted book is kept outside the repo, in the code cache (`docs/decisions/2026-11-12_building_code_text.md`).

The numbered steps:

| Step | Folder | What it is | Who changes it |
|---|---|---|---|
| 1 | `1_source_documents/` | Original documents, plus `sources.yaml` (link, download date, fingerprint) | Never edited |
| 2 | `2_extracted_text/` | Text pulled out of the documents | Generated by code only |
| 3 | `3_section_labels/` | Each clause labeled Rule / Flag / Reference / Not for checking, plus a topic | Drafted, checked by code |
| 4 | `4_term_definitions/` | How this place defines height, story, grade plane… | Drafted from the law, checked by code; architects answer the open questions |
| 5 | `5_zoning_rules/` | **The rulebook**, one file per district (`R-1b.yaml`) | Drafted, checked by code (architect approval deferred) |
| 6 | `6_coverage_report/` | Proof that no part of the documents was skipped | Generated by code only |
| 7 | `7_published_rulebooks/` | Each rulebook's checks, frozen as a certificate the checker reads at every check (`python -m rule_format publish`; a missing or out-of-date one: a zoning district's gives no report, a state law's gives no rows, needs review) | Generated by code; not committed while rules are draft; once approved, never changed |

## When the city changes its code

Download the new documents (step 1) and re-run the steps. Code compares the new draft with the current rulebook and lists **only the differences** for people to check. A published rulebook is never overwritten: a new version is published alongside it.

## Two different approvals

- **Rule approval** — once per code version, an architect would confirm each rule (step 5). Deferred for now (decided 2026-10-19): rules stay drafts, checked by code, and people read them through the rules spreadsheet. The approval fields are kept so it can be switched on later.
- **Project confirmation** — once per project, in Rhino: the architect confirms the facts about their site and design (lot, zone, use…).
