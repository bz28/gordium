# Maine's own law: commercial egress for a day-care centre

Law every Maine place would inherit (a Maine place lists this folder in its `jurisdiction.yaml` under `inherits:`; none does yet, so no design check runs it today). It is not a place: its settings file is `state.yaml`. Why these books, these copies, and how they are read: [docs/decisions/2026-11-20_commercial_egress_maine.md](../../../../docs/decisions/2026-11-20_commercial_egress_maine.md).

- **The books:** the **2009 International Building Code** (IBC) and **NFPA 101, Life Safety Code, 2012 edition**: the editions the architect's life-safety sheet cites (LS1.0, Children's Odyssey, 19 Libby Street, Portland, October 2016). Both apply to the same building; where both set a limit, **the stricter governs** (each pair's rule notes say which: the IBC's 75 ft common path over NFPA's 100 ft sprinklered; the IBC's 25 ft dead end, by exception 3, over NFPA's 50 ft sprinklered; NFPA's 150 ft travel from any point in a room over the IBC's 200 ft).
- **Brought in** (`1_source_documents/sources.yaml`, `brought_in`): from the IBC, 308.5 (Group I-4 day care), 508.2 (accessory occupancies, with Table 508.2.5), 1004.1 and Table 1004.1.1 (occupant load), 1008.1.2 (door swing), 1014.3 (common path), 1015.1, Table 1015.1, 1015.2 (exits and their remoteness), 1016.1 and Table 1016.1 (travel distance), 1018.1, Table 1018.1, 1018.2, 1018.4 (corridors and dead ends), 201 and every definition they use (by the book's italics); from NFPA 101, Chapter 16 (new day-care occupancies) and 17 (existing): occupant load, doors, dead ends, common path, travel distance, corridors; 6.1.14.4 and Table 6.1.14.4.1(b) (separated occupancies), Table 7.3.1.2 (occupant load factors), 3.1 and every Chapter 3 definition whose term those print.
- **The copies:** Public.Resource.Org's on the Internet Archive, kept in the code cache outside the repo (copyright: the repo keeps only short exact quotes with section, page and a link). Everything is verified against these copies only; **check against copies bought from ICC and NFPA**.
- **The IBC copy is OCR only.** Its PDF holds no page images, and the item's page images are made from the same OCR and print its errors (Table 1015.1 prints "1-4" for I-4 in the image itself). No reading independent of the OCR exists, so **every IBC number is read from an OCR copy only: not verified** (`text_verification.icc.ibc.2009.yaml`: each piece's numbers, with `not_verified` saying why; `rule_format/state_law.py` accepts such a file only with no second reading in it). **Every IBC requirement is therefore a flag** (always needs review, never passes): its check is kept as the drafted test and each worked example's `drafted_check` says what that test gives (`rule_format/code_numbers.py` refuses any rule of kind `rule` standing on these numbers). The OCR's meaning-changing misreads a quote holds ("1-4" for I-4, "I-hour" for 1-hour, "H-l" for H-1, "Sand U" for S and U, "5-1" for S-1) are named in each label's notes, never put right in the text. **Buy ICC's 2009 IBC**, record a second reading, and the IBC flags can become rules.
- **NFPA 101 2012 is NFPA's own PDF** (real text), so its numbers were read a second time from the page images (`text_verification.gov.law.nfpa.101.2012.yaml`: 143 pieces; the two tables are flagged, their cells read in a different order, the values the rules use compared row by row). NFPA rules are kind `rule` and use only those readings. NFPA prints feet as "ft", which the number reader reads as no unit; the quote's own "ft" makes such a number a length in feet (`code_numbers._in_feet`).
- **Rules:** `5_building_code_rules/drafted/general.yaml`, 60 hand-drafted rules (drafts: approval is deferred), for each part (story, space, corridor, means-of-egress door: `rule_format/parts.yaml`, each measure defined in words; no measuring code yet, so a check needs review until engineers write it) and for the whole building (its occupancy group, sprinkler system, new or existing: proposed measures, `5_building_code_rules/drafted/records/proposed_measures.yaml`, stated by the architect). Graded against the architect's hand check, `test_data/answer_keys/portland_me_19_libby_st/hand_check.yaml` (`rule_format/tests/test_maine_egress.py`): on the sheet's own numbers every rule's result (an IBC flag's drafted test) is the sheet's pass: travel 130'-8" (IBC 200 ft; NFPA 150 ft), common path 48'-6" (75 ft; 100 ft), dead end 21'-6" (under 2.5 x 10 ft; 50 ft), remoteness 183'-10" / 210'-2 1/2" = 0.8745 (one-third), storage 1,428 sf (10% of the story), corridors smoke partitions (NFPA 16.3.6(2)). The separation (Table 6.1.14.4.1(b)) needs review: the sheet does not name the other occupancy.
- **Not checked yet:** every piece labeled rule or flag has a rule (`6_coverage_report/*.rules.yaml`: `not_checked_yet` is empty for both books).

See `regulations/README.md` for what each numbered step means; step 5 here is `5_building_code_rules/`.

## Definitions

The IBC: a word printed in italics has Chapter 2's meaning (its preface; 201.1), matched by its letters so the OCR's run-together words still name it. NFPA 101 marks no defined word: by **3.1**, "The definitions contained in this chapter shall apply to the terms used in this Code", so every Chapter 3 term applies wherever the Code prints it, italics or not; every Chapter 3 definition whose term a brought-in piece prints is brought in. `4_term_definitions/definitions.yaml` holds the ones the rules measure with, keyed `ibc_` or `nfpa_`: a rule reads its own book's definition.

## What the books' text gets wrong or leaves odd

- **NFPA 17.3.6(1)** (existing day care) prints "spaces normally subject to **student** occupancy" where 16.3.6(1) prints "client" (p.183, line 82). Gordium's reading: the same spaces are meant (a day-care chapter's occupants are clients); for the architects to confirm. Its item (2) prints "with valve supervision" where 16.3.6(2) prints "approved, supervised"; read as the supervised system (the proposed measure `sprinkler_supervised_9_7`), also to confirm.
- **NFPA 17.2.6.3** prints "an approved automatic sprinkler system", without 16.2.6.3's "supervised": read as printed.
- **IBC 1018.2 exception 4** is read out of order by the OCR ("In Group E with a / having a required capacity of 100 or more. / corridor"); the book prints "In Group E with a corridor having a required capacity of 100 or more". Not used by a day-care rule.
- **The answer key's remoteness ratio** was written 0.8746; 183.833 / 210.208 is 0.87453, now 0.8745 there.

## Open questions (for Ben, the City of Portland or the State Fire Marshal)

1. **Which editions applied on the October 2016 permit.** MUBEC's rules (16-642 CMR, filed October 2010) adopted the 2009 I-codes; whether Portland enforced the 2009 IBC in October 2016 is the sheet's word, not yet the rule text's. Maine's Life Safety rule (16-219 CMR ch. 20) names the 2018 NFPA 101 today; in 2016 an earlier edition (2009, as Ben has it); the sheet's numbers match 2012.
2. **Maine's own modifications.** Today's 16-219 CMR ch. 20 sets a flat 20-ft dead-end limit, which the sheet's 21'-6" would fail (`general.ibc_1018_4_dead_end` and `general.nfpa_16_2_5_2_dead_end` record it as an open question with what was searched).
3. **Copies to buy:** ICC's 2009 IBC (the one thing keeping every IBC flag from becoming a rule) and NFPA 101 2012 (to confirm this copy).
